# KinShip v2 requirements (restart, Nov 2026)

Previous build (Node/Express/Prisma/React Flow) is scrapped. Mockup comes first; the stack was chosen on Nov 15 (see Decisions). Companion docs: `kinship-navigation.md` (tabs, Home, DNA badge, Add relative), `kinship-tree-views-and-dna.md` (tree views, spouse's family leaf, DNA), `kinship-color-schemes.md` (the four color schemes), `kinship-storage-encryption.md` (file encryption), `kinship-email-templates.md` (emails), `kinship-research-records-and-backup.md` (sources, places, events, stories, duplicate merge, backups), `kinship-family-health-history-report.md` (the doctor-visit report) and `kinship-release-and-deployment-plan.md` (versions, GitHub repo, Docker images, what ships when, update notice).

## Decisions
- **Stack (decided by JC, Nov 15):** **PostgreSQL 18** (supported to Nov 2030), a **TypeScript** API on Node, a separate **nginx** `web` container, and a **React** UI. Library picks inside that (Fastify, Kysely with plain SQL migrations, Vite, own SVG tree drawing) are proposed and listed in the release plan, section 6.
- Deploy: Docker Compose (file named `compose.yml`) + Postgres 18. Three services: `web` (nginx serving the static React UI, the only published port, :8080 plain HTTP, proxies `/api`), `api` (internal only, runs migrations at startup) and `db`. Same version tag for web and api. User's external reverse proxy handles TLS/certs and sees one upstream. Cloudflare optional in front only.
- **Distribution (decided by JC, Nov 15):** public GitHub repository **`officialJCReyes/kinship`, public from day one**, license **AGPL-3.0**. Images are built by GitHub Actions and published to GitHub Container Registry (`ghcr.io/officialjcreyes/kinship-web` and `kinship-api`, amd64 and arm64). Semantic versioning, 0.x releases up to a trimmed **v1.0** (core, through reports and GEDCOM); S3, MapTiler, Word, family book and DNA ship in 1.1 to 1.3. Full plan in `kinship-release-and-deployment-plan.md`.
- **Update notice (decided by JC, Nov 15; built in the mockup under Admin → Updates):** the SuperAdmin is notified when a newer version exists. **A toggle inside the app, not an environment variable; no email.** Clicking the notice opens a popup of the changes. After an update, a **"What's new" popup** shows the changelog **to every admin (SuperAdmin and Family Admins) at their next sign-in**. **If the release has a database migration or a breaking change, the popup warns the SuperAdmin to take a backup first** (shows the age of the last backup and a Back up now button). An **automatic safety copy of the database before each migration is on by default** (can be turned off in Admin → Updates). The check reads GitHub's public release list and sends nothing about the install. Details in the release plan, section 7. The account menu also has an **About KinShip** page (version, AGPL license, source-code link).
- Medical privacy enforced by Postgres row-level security (app connects as non-owner role; separate owner role runs migrations).
- Schema changes via versioned migrations, never `db push`.
- Audience: starts as one user, grows to roughly 10 to 50+ people. Public internet, login required.
- UI: English only at launch, all strings as translation keys so the community can add locales. Desktop-first dense layout, mobile-friendly. **Pages are centered in the window (Home, profile, reports, Admin and so on); only the tree canvas uses the full width (JC, Nov 14).**
- No AI features. Reports and summaries are generated from fixed templates and graph logic so output is repeatable and nothing is invented.
- Branding: logo kit delivered (sailboat with leaf sail; wordmark "KinShip"). Palette: deep teal #1E4D4A, leaf green #4F8A4B, amber #F2A541, cream #FBF6EE (dark-mode leaf #8CC488). **Four color schemes (Forest, Warm sand, Slate blue, Graphite) are offered to every end user, in My settings and in first-run setup (decided by JC, Nov 14); see `kinship-color-schemes.md`.** Kit includes SVG and PNG marks, horizontal/stacked/reversed logos, app icons, favicon.
- File storage is switchable: local volume or S3/S3-compatible (AWS S3, Backblaze B2, Cloudflare R2, MinIO). Files stay private and are **encrypted by KinShip before they are stored** (`FILE_ENCRYPTION`, key in `FILE_ENCRYPTION_KEY`); the app checks permission and streams them. Admin page can run a migration between backends. (Release plan: local encrypted storage from 0.2, S3 and the migration tool in 1.1.)
- Email is switchable: Resend API or any SMTP provider. Used for invites, password resets and notifications.
- **Map tiles (decided by JC, Nov 14):** **default is OpenStreetMap when nothing is configured** (`MAP_PROVIDER` empty or `osm`, no key). Support for one keyed provider is added, **MapTiler** (my recommendation, JC accepted), chosen with `MAP_PROVIDER=maptiler` and `MAPTILER_API_KEY`. The deployer picks; more providers can be added later. The OSM public tiles are for light use only, so a busy install should switch to a keyed provider. In the mockup the **Deployment page has a Map tiles card** showing both setups, Admin → System has a preview switch, and the compose example has `MAP_PROVIDER`. (MapTiler ships in 1.1.)
- **Secrets (confirmed by JC):** S3 keys, Resend key, SMTP credentials, the file key, the backup passphrase and the map provider key live in a `.env` file (mode 600) or Docker secrets (`*_FILE`), never in the database or Admin page. Admin page shows read-only status, test buttons and the migrate action. Non-secret settings (notification defaults, send time, time zone, backup schedule and retention, the update-check toggle) are editable in Admin.
- **Backups (JC asked, Nov 14):** built in, no extra container. `BACKUP_ENABLED`, `BACKUP_DEST` (`local` or `s3`), `BACKUP_PASSPHRASE`. One encrypted archive of the Postgres dump plus media files. Admin → Backups (SuperAdmin) has Back up now, Test the latest backup, a list with Download and Restore, and the command line. The backup does **not** include the file key or the passphrase, which the deployer must store separately. See `kinship-research-records-and-backup.md`. The automatic safety copy before a migration is separate from these backups (see the update notice above).
- Notifications: birthdays (lead time: on the day, 1 day, 1 week; email and/or in-app bell), optional anniversaries, remembrance days, weekly digest (off by default), and "an admin edited my medical record". Per-user settings with SuperAdmin defaults. **Children under 18 are excluded from birthday reminders (confirmed).** A daily in-app job sends them; no separate scheduler container. The SuperAdmin's bell also carries the update notice (in-app only).

## Navigation (decided; see `kinship-navigation.md`)
Admins see five header tabs: Home, Family tree (Chart, Relationship finder), Media, Archive (Timeline & map, **Sources, Places, Stories**, Reports), Health and DNA. Members and Users see the first four. **Health and DNA live on each person's profile** (tabs Medical history and DNA); the Health and DNA header tab is an admin-only overview. The profile tabs are Facts, Events, Stories, Photos & documents, Medical history and DNA. The chart's view switcher is one icon at the top right that expands to icon-only options (built). Account menu (avatar pill) holds My profile, My settings, Import & export, Admin (admins only), Deployment, **About KinShip**, Sign out. The person panel sits left of the tree and collapses to a rail. Home → Jump to has **Health history for my doctor**. Admin tabs: Users, Roles & access, Sign-in & SSO, Storage & email, Backups, **Updates**, Duplicates, Emails, Languages.

**Add relative (redesigned Nov 14 from JC's MyHeritage screenshots):** a diagram of the selected person with their parents, partners, siblings and children as cards, each with a "+" to add that kind of relative, then a short form. Two layouts: a person with parents on the tree, and a person with none. Details in `kinship-navigation.md`.

**A spouse's family (decided by JC, Nov 14):** one tree. An in-law's own parents are hidden in the main chart and opened with a small logo-green leaf on the in-law's card, which flips the chart to that family; there is no back button because both views are full charts. Details in `kinship-tree-views-and-dna.md`.

## Roles and edit scope (names changeable, access levels fixed)
- SuperAdmin, Family Admin, Member, User. Baseline User sees all public tree data and profile photos.
- **Admins edit everything on the tree.** **Members can edit only their own profile** (their facts, their own relationships, their own photo). Users cannot edit the tree. In the mockup, other people's edit buttons are disabled for a Member with the tooltip "You can only edit your own profile".
- **Members can add descendants only (decided by JC, Nov 14):** on their own profile they can add children (and through them grandchildren). They cannot add parents, partners, siblings or custom-label relatives; for those they ask an admin. In the mockup a Member's Add relative dialog offers only "Child" with a note saying so. Choosing the child's other parent from existing partners or "not on the tree" still works.
- **Members can add sources (decided by JC, Nov 15):** to the Sources library and as citations and files on any person's facts (they still cannot change the fact itself). Admins and Members can also add places and stories; Users can only read.
- Every account can edit the medical record of its own linked person, whatever its role.
- Custom conditions and cancer types (shared lists): merging and renaming is an **admin** task. Merging duplicate people and places is also an admin task.
- **Update notices and the update-check settings are for the SuperAdmin only. The "What's new" popup after an update is shown to every admin (SuperAdmin and Family Admins).**

## Medical visibility (private by default, shared person by person)
- **Decided by JC (Nov 14):** health information is private. A living person's record is visible only to that person until they **share it with specific individuals** (people who have accounts). There is no "all family accounts" or role-wide option any more. **Admins have no special access:** an admin sees a record only if that person shared it with them (or the person is deceased). Role does not matter; sharing is per person.
- After death every record becomes visible to all accounts. **A deceased person's cause of death (a field on the death fact) is visible to every account.**
- Conditions marked Private stay visible only to the person while living (sharing does not reveal them, even to the people chosen). After death they are visible.
- Admins can edit another person's record only when it is visible to them (shared with them, or the person is deceased); every edit is written to the change history and the person is notified.
- Reports, the patterns lists, the medical patterns report and the family health history report count only records and conditions the viewer can already see, and say how many relatives were left out because they are not shared or have no record.
- The mockup has checkboxes under "Who can see my record" listing the other people with accounts. Sharing and un-sharing are written to the change history.

## DNA visibility (decided by JC, Nov 14)
DNA results (tests, haplogroups, ethnicity estimate) are **visible to every account, living or deceased**. There is no sharing choice. Match lists and raw files stay private to the tested person (assumption: JC did not say otherwise, and they name living people who never joined KinShip). Admin upload on someone's behalf still needs a permission checkbox. Details in `kinship-tree-views-and-dna.md`. In the release plan the DNA tab ships in 1.2 and match lists in 1.3.

## Sources, places, events and stories (decided by JC, Nov 14; see `kinship-research-records-and-backup.md`)
- **Sources on any fact, like MyHeritage.** Birth, death and cause of death in Edit details each have a Sources & files panel (pick a library source or name a new one, page or record number, reliability, link, file). The profile shows each fact with citations, file chips and a "+ Source or file" button. Reliability: Primary, Secondary, Questionable.
- **Cause of death** is a field under the death date and place, with its own sources and files.
- **More event types** (occupation, residence, education, military, immigration, emigration, naturalization, baptism, burial, census, award, religion, custom label) with date, place, details, sources and files.
- **Sources library** (Archive → Sources, with Repositories) and **Places library** (Archive → Places: kind, part of, coordinates, other names, duplicate merge). **Stories** (story, note, recording, research note; admins-only option) on the Archive → Stories page and each profile.
- **Duplicate merge** (Admin → Duplicates): fixed-rule suggestions, field-by-field choice, blocked when one record is living and the other deceased, medical records never merged, never automatic, **undo for 30 days (decided by JC, Nov 15)**.

## Relationship finder
- Pick any two people with a searchable picker (type a name, year or place; arrow keys and Enter work). Swap button. Shows "<B>'s relationship to <A>" plus a diagram of the path, with the shared ancestor(s) at the top and each person's line down to them. Details switch: Basic or with birth places. Quick example pairs in the mockup.
- Names are worked out from the tree only: find the closest shared ancestor, count generations up from each person (dA, dB). Direct line gives parent, grandparent, great-grandchild and so on. dA=dB=1 is sibling; dA=1 with dB>=2 is niece/nephew (grand, great-grand...); dB=1 with dA>=2 is aunt/uncle (great-...). Both >=2 is cousin: level = smaller count minus 1 (first, second, third...), "removed" = difference between the counts (once, twice...).
- Half: a single shared ancestor gives half (Half-brother, Half-aunt, Half first cousin once removed); a shared ancestor couple gives full.
- Marriage links give in-law and step names (Sister-in-law, Father-in-law, Daughter-in-law, Stepbrother, Stepmother, Step-grandmother, Wife's nephew, Stepbrother's son). Current marriages (Married, Widowed, Separated) count.
- **Divorce (decided):** a divorce does not create or keep in-law names. A former partner of a blood relative is described plainly ("Father's ex-wife"). Descendants still find the person through blood: Leo finds Elena as Grandmother after her divorce from Daniel. A current spouse of a grandparent is Step-grandparent.
- A "What 'once removed' means" side panel appears for removed cousins (added in another session): shows each person's generation count below the shared ancestor, how the cousin number and the removed number are worked out, and that the term reads the same from either side.
- Generation note, list of closest common ancestors, Print and Download PDF buttons.

## Reports (no AI)
- **Life summary** for any person, living or deceased: Early life (birth, parents, siblings with relationship names), Family (each marriage with date, place, how it ended, children together, children with someone else), Death and family left behind (age, survivors: spouse, children, grandchildren, great-grandchildren). Optional sections: health history on record (only if the viewer may see that record; cause of death shown separately), life events list, citations and sources as numbered footnotes with links.
- Living children (under 18) get only name, birth year and parents. Living people's private conditions are visible only to that person.
- **Family health history (added Nov 15, for a doctor visit):** a one-page summary of the questions a PCP asks. Checklist (heart disease, blood pressure, cholesterol, diabetes, stroke, cancer by type, osteoporosis, thyroid, dementia, mental health) with which relative and the age at diagnosis, then tables for parents, brothers and sisters, children and optionally grandparents, aunts and uncles (age or age at death, conditions with age at diagnosis, cause of death). Names off by default; "unknown" is never shown as "none"; private conditions of living relatives never appear; own conditions optional; can be made for a child; Copy as text. Details in `kinship-family-health-history-report.md`.
- **Medical patterns** for a person: conditions that repeat among their blood relatives (in-laws and step relatives left out), with relationship, cancer type and since-year, a count, a flag when the person has it too, and a note on how many relatives were left out (not shared, or no record). States that it is family history, not a risk calculation or medical advice.
- **Family group sheet (added at JC's request, Nov 14):** the standard one-page genealogy record for a couple. Pick a person and, when they have several relationships, which one. Shows the husband and wife (born, place, died, father, mother), the marriage or relationship (status, date, place, end date) and a table of the couple's children in birth order (name, sex, born, place, died, spouse). Living children under 18 show name, sex and birth year only. A person with no relationship gets a message instead. In the mockup the husband and wife labels follow gender, and sources are not yet listed on the sheet.
- **Family book**: printable book for the descendants of a chosen person (plus spouses): cover page, contents, one chapter per person (the life summary, one page each when printed) and an index of names. Options: life events, health histories (off by default, and only what the viewer can see), sources. (Ships in 1.1.)
- **Descendants** outline with spouses, **Ancestors** by generation with relationship names, **Data check** (missing places, events without sources, branches with no parents).
- Output: print or save as PDF, Word (.docx), plain text. Person picker is searchable. (Print, PDF and text in 1.0; Word in 1.1.)
- Idea not yet in the mockup: birthday and anniversary list.

## Partner relationships
- Status list (fixed, from JC's reference screenshot): Married, Divorced, Separated, Widowed, Engaged, Partner, Friends, Annulment, Unknown, Other.
- Each relationship has: status, marriage date (precision Exactly/About/Before/After), marriage place, and an end date shown only for Divorced (divorce date), Separated (separation date) and Annulment (annulment date).
- A person can have several relationships over time. Changing a status never removes children.
- **Unmarried parents:** when a child has two parents who are not linked yet, the app creates a relationship for them with status **Unknown** (not Partner). The Add relative dialog says so.
- Labels follow status and gender (Wife, Ex-wife, Wife (separated), Fiancée, Wife (widow), Late wife and so on). Derived relatives: step-parents and stepchildren (through a Married or Widowed relationship), half-siblings.
- **Widowed is automatic.** Marking a person deceased (Edit details, status Deceased) sets their Married relationships to Widowed and shows a toast saying their medical history is now visible to every account. Marking them living again reverts only the ones set automatically. If a marriage ended earlier, an admin changes the status by hand (for example Divorced), and that manual choice is kept. **Widowed draws like Married (solid line)** because the deceased marker already shows the spouse has died.
- **Children hang from the relationship.** A child with both parents on the tree is drawn from the midpoint of that couple's line, so kids from a previous relationship stay with that union. A child with only one parent on the tree is drawn from that parent alone. Add relative asks for the other parent: a partner on the tree, or "not on the tree".
- Profile shows a card per relationship with dates, place, children together, the partner's children from another relationship (labelled "with <other parent>" or "other parent not on the tree", and "your stepson/stepdaughter" when married), and what each person did afterwards.
- **Tree line convention (no letter badges):** solid line = together (Married, Engaged, Partner, Widowed). Dotted line = ended or not a marriage (Divorced, Separated, Annulment, Friends, Unknown, Other). Clicking a couple line opens that relationship to edit (if the role may); hover shows the status.

## Names, dates and photos (added in other sessions)
- **Maiden and married surnames.** People have a birth (maiden) surname and an optional married surname. Fields appear when a relationship is Married (Add relative, first-run setup, Edit details). A setting picks which surname shows on the tree (married when set, or birth). Both stay on the profile under Facts.
- **Dates.** Entered as YYYY, YYYY-MM or YYYY-MM-DD with a live preview and validation. Display format is a per-user setting in My settings (Jan 1, 2026; 1 Jan, 2026; 1 Jan 2026; January 1, 2026; 2026-01-01; 01/01/2026; 01/01/2026 day first). The tree, profile, birthday list and reports follow it.
- **Profile photos.** Any role that may edit a person can upload a photo by clicking their avatar (profile header, person panel, medical page). The photo shows on the tree node, relationship cards and medical page. "Set as profile photo" from Media also works.
- **First-run setup wizard** (seven steps with progress bar): Account (SuperAdmin name, email, password), Tree (name, like "Hale Family", and the color scheme swatches), You (given name, surname, birth date, gender), Partner (relationship status, birth surname, optional married surname), Parents (father, mother, living or deceased), Children (several rows, choose the other parent for each, or "not on the tree"), Review (preview of the people created, and a note about the daily update check and where to turn it off). The screen never appears once an account exists.

## Medical history (self-service)
- Every account can edit the medical record of its own linked person (blood type, conditions with since-year, status, optional source URL). It appears on the person's profile in the **Medical history** tab.
- Statuses: Active, Managed, Monitored, In remission, Resolved.
- Conditions are chosen from a searchable list of common conditions (about 70, grouped by category, matches on common names such as "high blood pressure"). If nothing matches, the user types a new name and adds it; custom conditions join the family list for everyone. Admins can merge duplicates later. Conditions already on the person's record are shown as unavailable.
- **Cancer is one condition with a required type.** Choosing Cancer reveals a "Type of cancer" searchable field (about 24 common types such as Breast, Prostate, Lung, Colorectal, Skin (melanoma), Leukemia, Lymphoma, plus Unknown type). If the type isn't listed, the user types it and adds it as a new type, which joins the shared list. A person may have several cancer entries. Shown as "Cancer · Breast"; family patterns list "Name (breast)".
- Sharing: **private by default; share with specific people** (see Medical visibility above).

## Tree views and DNA (see `kinship-tree-views-and-dna.md`)
Four chart views (Family tree, Pedigree, Fan, Descendants). DNA results from third-party providers, several per person, uploaded by the person or by an admin on their behalf, visible to every account, with a tree check of matches (own page only), Y-DNA and mtDNA lines, and an orange tree badge for everyone with an upload.

## v1 features
**The mockup shows the whole wish list; the release plan splits it (decided by JC, Nov 15).** **v1.0 contains:** tree canvas + collapsible person panel; four chart views; Home with Memory of the day; person profile with Edit details (name, gender, birth, living/deceased, cause of death); required given name and surname, maiden and married surnames; partner relationships with statuses and dates; relationships with custom labels overriding derived titles (e.g. Godmother); **sources and files on birth, death, cause of death and events, with a Sources library, repositories and reliability**; **typed life events**; **Places library**; **Stories and notes**; **duplicate merge**; **backup and restore**; photos and documents with a family-wide Media page and profile photo upload (encrypted local storage); medical history with blood type, searchable condition list and per-person sharing; relationship finder with cousin levels; core templated reports (life summary, **family health history for a doctor**, medical patterns, family group sheet, outlines, data check; print, PDF and text); timeline and map (OpenStreetMap by default); GEDCOM import and export; flexible date entry and per-user date format; accounts optionally linked 1:1 to a person; first-run setup wizard; Authentik OIDC SSO plus local login fallback; email and notification setup; birthday notifications; four color schemes; update notice, What's new popup and About page. **Moved to 1.x:** S3 storage and the backend migration tool, MapTiler, Word output and the family book (1.1); DNA tab (1.2); DNA matches (1.3). The order of every release is in `kinship-release-and-deployment-plan.md`.

## Candidate features not yet chosen (from the Gramps / MyHeritage / AncestryDNA comparison)
Suggest-a-change approval flow for Members; tree-wide change history with undo; people list and search; a rule-based data check with quick fixes; two-factor login and passkeys for local accounts; calendar feed (ICS); Gramps XML import and a GEDCOM import preview; hourglass chart and paternal/maternal line highlight; alternate names; date ranges; research to-dos; DNA cM lookup, match labels and notes. Deliberately skipped: record and tree matching against outside databases, AI photo tools, ethnicity calculation from raw files. (The release plan places these in 1.4 and 1.5.)
