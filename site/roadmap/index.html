How releases work

Versioning

Semantic versions. Before 1.0 each minor release is a milestone and patches are bug fixes only. The version number is not a measure of size, so new features after 1.0 do not need a 2.0.

Your data

Migrations only move forward and keep your data. Every upgrade path is tested, and the app asks you to back up first when a release changes the database.

Support

Only the newest release is supported, with fixes shipped as a new patch. That keeps one maintainer's work honest, so upgrading is made as safe and easy as possible.

Something missing?

Bugs and work left out of a release are tracked as issues on GitHub. Questions and ideas are welcome there too.
